# 插件门卫（astrbot_plugin_guard）

> ⚠️ **测试版（alpha）**
> 本版只在单机上跑通过主流程，没有经过多环境、多版本验证。生产环境请自担风险。
> 遇到问题欢迎回报，但别指望它现在就稳。

思路借自 [`Noob-stupid/dsh-plugin-gating-hub`](https://github.com/Noob-stupid/dsh-plugin-gating-hub)（MIT）——只取「回滚点 + 失败回滚」那一截，它的预检与插件市场那层没搬。


只做事后补救：给插件留快照，崩了能一键退回上一份。

## 为什么只做「事后」

AstrBot 装插件是内核自己干的——WebUI 点安装，它把包解开覆盖目录，再重载。第三方插件没有「装前」这个钩子，拦不住，就只能救。

所以这里不做预检、不拦人、不管市场，只守三件事。

## 三件事

| 命令 | 做什么 |
|---|---|
| `/pguard snap [插件名]` | 拍快照。不写名字就拍全部 |
| `/pguard list` | 列出所有快照 |
| `/pguard rollback 插件名 [时间戳]` | 退回最近一份，或指定那一份 |

## 开机自检

插件加载后等 30 秒，等启动日志写齐，再从「上一次启动」读到「本次启动」，把每一行 `Loading plugin X ...` 和后面配对的 `Plugin X (版本) by ...` 对一遍。

- 开始了、没成功、也没有快照 → 记一笔告警
- 有快照 → 自动回滚（`auto_rollback` 默认开，配置里能关）

日志里的干扰是个坑：工具调用的长参数行里也会出现「Loading plugin」几个字，宽松匹配会被骗。所以只认 `star_manager` 打的那一行。

## 回滚时原目录不删

它做的是 `shutil.move` 改名，不是删除。万一回滚本身出错，坏的那版和好的那版都还在盘上。

## 安装

```
装到 data/plugins/astrbot_plugin_guard/
依赖：无（标准库）
```

装完重载插件。首次用先 `/pguard snap`，一份快照大概零点几秒。

## 没有验证过的部分

写在这儿，省得别人自己撞。**已验的**：快照、列表、回滚——造过一个假插件，拍快照、改坏、回滚，内容原样回来。

**没验的**：

- **开机自检自动回滚整条路**。判定逻辑验过（扫日志能认出 23 个插件、0 个可疑），但「某个插件真崩了、自检真把它退回去」这件事没发生过一次。等于保险丝装好了，没跳过闸。
- **多个插件同时坏**。一次只退一个的路径都没走通，更别说一串。
- **大目录**。最大一份快照 24.5 MB（`private_companion`），再大没试过；磁盘满、写一半断电也没试。
- **跨平台**。只在 Windows 上跑过。路径分隔符、文件锁、`shutil.move` 的语义在 Linux/macOS 上都还没看。
- **AstrBot 大版本升级**。快照只存插件目录，不存配置；升级把 `backend/` 换了之后，旧快照里的插件可能本来就跑不起来。

## 已知限制

- 回滚只换目录，不改内存里正在跑的那份代码——得靠重载或重启才真生效。
- 自检只在启动后跑一次，中途崩的它不知道。
